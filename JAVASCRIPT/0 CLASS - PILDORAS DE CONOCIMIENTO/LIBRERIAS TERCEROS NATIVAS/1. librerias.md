# Librerías de terceros versus librerías nativas

## 1. Funciones nativas de JavaScript

JavaScript ya proporciona muchas funciones y métodos que podemos utilizar directamente.

Por ejemplo:

```js
setInterval();
clearInterval();
setTimeout();
parseInt();
Math.random();
```

No tenemos que programarlos nosotros porque ya forman parte de JavaScript o del entorno en el que se ejecuta.

Por ejemplo:

```js
const intervalo = setInterval(() => {
  console.log("Hola");
}, 1000);

clearInterval(intervalo);
```

`clearInterval()` es una **función nativa**, proporcionada por el entorno de JavaScript.

> **Importante:** `clearInterval()` no es una librería nativa. Es una función nativa.

---

## 2. ¿Qué ocurre cuando JavaScript no tiene una función que necesitamos?

Imaginemos que queremos comprobar si un campo de formulario está vacío.

Podríamos pensar que existe una función:

```js
isEmpty(valor);
```

Pero JavaScript no proporciona una función nativa general llamada `isEmpty()`.

Por eso podemos combinar funciones y propiedades que sí existen:

```js
valor.trim().length === 0;
```

Por ejemplo:

```js
const nombre = document.querySelector("#nombre");

if (nombre.value.trim().length === 0) {
  console.log("El campo está vacío");
}
```

Aquí:

- `trim()` elimina los espacios del principio y del final.
- `length` nos indica cuántos caracteres quedan.
- `=== 0` comprueba si no queda ningún carácter.

---

# 3. ¿Tenemos que programarlo todo nosotros?

No.

Hoy en día **no siempre es necesario reinventar la rueda**.

Si una funcionalidad que necesitamos ya ha sido creada por otros programadores, podemos utilizar una **librería de terceros**.

Una librería de terceros es un conjunto de código creado por otros programadores que podemos incorporar a nuestros proyectos para reutilizar sus funcionalidades.

Por ejemplo, existe una librería muy conocida llamada **Lodash** que proporciona una función llamada `_.isEmpty()`.

En lugar de escribir:

```js
nombre.value.trim().length === 0;
```

podemos utilizar:

```js
_.isEmpty(nombre.value);
```

---

# 4. Ejemplo con Lodash

Podemos incorporar Lodash a nuestro HTML:

```html
<script src="https://cdn.jsdelivr.net/npm/lodash/lodash.min.js"></script>
<script src="script.js"></script>
```

Y después utilizar sus funciones desde nuestro JavaScript:

```js
const nombre = document.querySelector("#nombre");

if (_.isEmpty(nombre.value)) {
  console.log("El campo está vacío");
}
```

La comparación sería:

### Sin librería

```js
if (nombre.value.trim().length === 0) {
  console.log("El campo está vacío");
}
```

### Utilizando una librería de terceros

```js
if (_.isEmpty(nombre.value)) {
  console.log("El campo está vacío");
}
```

La ventaja es que **no tenemos que implementar nosotros esa funcionalidad**.

---

# 5. ¿Qué significa `_`?

El símbolo `_` es simplemente el **nombre que Lodash utiliza para identificar su librería**.

Por eso escribimos:

```js
_.isEmpty();
```

Podemos interpretarlo como:

```text
_        → Lodash
  .
isEmpty  → función que queremos utilizar
```

El `_` **no es una palabra especial de JavaScript**.

Los creadores de Lodash podrían haber utilizado otro nombre, pero eligieron `_` porque es corto y fácil de escribir.

Por ejemplo:

```js
_.isEmpty(valor);
_.isArray(valor);
_.isNumber(valor);
```

El punto (`.`) permite acceder a una función o propiedad del objeto que representa la librería.

---

# 6. Una librería no es magia

Una librería de terceros no crea nuevas capacidades mágicas en JavaScript.

Alguien ha programado esas funcionalidades utilizando código y después las ha organizado para que otros programadores puedan reutilizarlas.

Por ejemplo, nosotros podríamos crear:

```js
function isEmpty(valor) {
  return valor.trim().length === 0;
}
```

Y después utilizarla:

```js
if (isEmpty(nombre.value)) {
  console.log("El campo está vacío");
}
```

La librería simplemente nos permite **reutilizar código que ya ha sido creado por otra persona**.

---

# 7. También podemos crear nuestra propia librería

Si tenemos varias funciones que utilizamos habitualmente, podemos agruparlas en un archivo.

Por ejemplo:

```text
proyecto/
│
├── index.html
├── script.js
└── utilidades.js
```

En `utilidades.js` podemos tener:

```js
function isEmpty(valor) {
  return valor.trim().length === 0;
}

function isEmail(valor) {
  return valor.includes("@");
}

function isPositiveNumber(valor) {
  return Number(valor) > 0;
}
```

De esta forma tenemos un conjunto de funciones reutilizables.

Podemos utilizar esas funciones desde diferentes partes de nuestro proyecto.

Esto nos permite crear nuestra propia **librería de utilidades**.

---

# 8. Diferentes tipos de código reutilizable

Podemos distinguir:

| Tipo                     | Ejemplo           | ¿Quién lo crea?      |
| ------------------------ | ----------------- | -------------------- |
| **Función nativa**       | `clearInterval()` | JavaScript / entorno |
| **Método nativo**        | `"hola".trim()`   | JavaScript           |
| **Función propia**       | `isEmpty()`       | Nosotros             |
| **Librería de terceros** | Lodash            | Otros programadores  |
| **Librería propia**      | `utilidades.js`   | Nosotros             |

---

# 9. La idea importante

No tenemos que programar siempre todo desde cero.

Cuando necesitamos una funcionalidad podemos plantearnos:

```text
¿JavaScript ya tiene una función para esto?
             │
             ├── SÍ → utilizamos la función nativa
             │
             └── NO
                  │
                  ↓
        ¿Existe una librería que lo haga?
                  │
             ┌────┴────┐
             │         │
            SÍ        NO
             │         │
             ↓         ↓
      Utilizamos    La creamos
      la librería   nosotros
```

Por ejemplo, para comprobar si un campo está vacío:

```text
JavaScript no tiene isEmpty()
             ↓
Podemos hacerlo nosotros
             ↓
valor.trim().length === 0
```

Pero también:

```text
JavaScript no tiene isEmpty()
             ↓
Existe una librería de terceros
             ↓
Lodash
             ↓
_.isEmpty(valor)
```

---

# 10. NO REINVENTAR LA RUEDA

> **Programar no significa hacerlo todo desde cero.**
>
> Primero debemos saber qué funcionalidades nos proporciona JavaScript.
>
> Si no existe lo que necesitamos, podemos programarlo nosotros.
>
> Y si alguien ya ha creado y probado esa funcionalidad, podemos reutilizarla mediante una librería de terceros.

Esto es también una cuestión de **reutilización de código**: aprovechamos código que ya existe en lugar de volver a escribirlo cada vez.
