# Cómo usar nuestras propias librerías en JavaScript: forma antigua y forma moderna

Cuando un proyecto crece, conviene separar el código en varios archivos. Por ejemplo, podemos tener una **librería propia** (`miLibreria.js`) con funciones reutilizables y un **script principal** (`script.js`) que las usa.

Hay dos formas de conectar esos archivos:

| Forma       | Cómo se comparte el código            | Desde cuándo     |
| ----------- | ------------------------------------- | ---------------- |
| **Antigua** | Scripts clásicos (variables globales) | Desde siempre    |
| **Moderna** | Módulos (`export` / `import`)         | Desde ES6 (2015) |

Las dos funcionan en todos los navegadores actuales. Se mantienen las dos porque millones de webs y librerías antiguas siguen usando la forma clásica.

Para explicarlas usamos el mismo ejemplo: un campo de texto y un botón que comprueba si el campo está vacío.

---

## 1. Forma antigua: scripts clásicos

Durante muchos años JavaScript **no tenía forma de importar archivos**. La única opción era cargar varios `<script>` en el HTML, y todos compartían el mismo espacio global: lo que declara un archivo lo pueden usar los demás.

Así funcionan también muchas librerías conocidas. jQuery, por ejemplo, crea una variable global `$` que cualquier script cargado después puede usar.

### `miLibreria.js`

La función se declara normalmente, sin nada especial. Al cargarse, queda disponible en el espacio global.

```js
function isEmpty(valor) {
  return valor.trim().length === 0;
}
```

### `script.js`

Usa `isEmpty` directamente, sin indicar de dónde viene. La encuentra porque `miLibreria.js` se ha cargado antes.

```js
const nombre = document.querySelector("#nombre");
const btnComprobar = document.querySelector("#btnComprobar");

btnComprobar.addEventListener("click", () => {
  if (isEmpty(nombre.value)) {
    alert("El campo está vacío");
  } else {
    alert("El campo tiene contenido");
  }
});
```

### `index.html`

Hay que cargar **los dos archivos**, y **primero la librería**:

```html
<!doctype html>
<html lang="es">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <script src="miLibreria.js" defer></script>
    <script src="script.js" defer></script>
    <title>Mi librería</title>
  </head>
  <body>
    <input type="text" id="nombre" placeholder="Escribe tu nombre" />
    <button id="btnComprobar">Comprobar</button>
  </body>
</html>
```

### Problemas de esta forma

- **El orden en el HTML es obligatorio.** Si `script.js` se carga antes que `miLibreria.js`, falla con el error `isEmpty is not defined`.
- **No se sabe de dónde viene cada cosa.** Leyendo `script.js` no hay ninguna pista de que `isEmpty` está en `miLibreria.js`.
- **Choque de nombres.** Si dos archivos declaran una función o variable con el mismo nombre, una pisa a la otra sin avisar.

---

## 2. Forma moderna: módulos

Con ES6 llegaron `export` e `import`. Cada archivo es un **espacio cerrado**: nada sale de él salvo lo que se **exporta**, y nada entra salvo lo que se **importa**.

### `miLibreria.js`

Se añade `export` delante de lo que queremos compartir:

```js
export function isEmpty(valor) {
  return valor.trim().length === 0;
}
```

### `script.js`

Se añade `import` al principio, indicando **qué** se importa y **de qué archivo**:

```js
import { isEmpty } from "./miLibreria.js";

const nombre = document.querySelector("#nombre");
const btnComprobar = document.querySelector("#btnComprobar");

btnComprobar.addEventListener("click", () => {
  if (isEmpty(nombre.value)) {
    alert("El campo está vacío");
  } else {
    alert("El campo tiene contenido");
  }
});
```

### `index.html`

Solo se carga el **script principal**, con `type="module"`. `miLibreria.js` no aparece en el HTML porque lo carga el propio `import`:

```html
<!doctype html>
<html lang="es">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <script type="module" src="script.js"></script>
    <title>Mi librería</title>
  </head>
  <body>
    <input type="text" id="nombre" placeholder="Escribe tu nombre" />
    <button id="btnComprobar">Comprobar</button>
  </body>
</html>
```

### Lo que cambia con los módulos

- **El orden en el HTML deja de importar.** Cada archivo declara sus propias dependencias con `import`.
- **Cada `import` dice de dónde viene cada cosa**, así que el código se entiende sin mirar el HTML.

---

## 3. Exportar e importar varias cosas

Una librería normalmente tiene varias funciones. Se exportan todas las que queramos compartir:

```js
// miLibreria.js
export function isEmpty(valor) {
  return valor.trim().length === 0;
}

export function isNumber(valor) {
  return !isNaN(Number(valor));
}

// Esta no se exporta: solo se puede usar dentro de miLibreria.js
function funcionInterna() {
  // ...
}
```

Y se importan solo las que necesitemos, separadas por comas:

```js
// script.js
import { isEmpty, isNumber } from "./miLibreria.js";
```

Lo que no se exporta queda **privado** dentro del archivo. En la forma antigua esto no era posible: todo lo declarado quedaba a la vista de los demás scripts.

---

## 4. Comparación

|                                       | Forma antigua (script clásico) | Forma moderna (módulo)             |
| ------------------------------------- | ------------------------------ | ---------------------------------- |
| Cómo se carga en el HTML              | `<script src="..." defer>`     | `<script type="module" src="...">` |
| Archivos que hay que poner en el HTML | Todos                          | Solo el principal                  |
| Orden de carga en el HTML             | Importa                        | No importa                         |
| Se sabe de dónde viene cada cosa      | No                             | Sí, lo indica el `import`          |
| Choque de nombres                     | Posible                        | No                                 |
| Funciones privadas                    | No                             | Sí (lo que no se exporta)          |

---

## 5. React

- **En React, Vite y herramientas similares:** todo funciona con módulos. Por eso en React siempre se escribe `import`, por ejemplo `import { Header } from './Header'`.
